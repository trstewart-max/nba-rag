Retrieval-augmented QA · 2025-26 NBA season · runs locally

Ask a question about the season. Get an answer that cites its sources, or a straight “I can't tell from the data.”

A RAG pipeline over real box scores and play-by-play. SQL and Python do the counting, pgvector finds the right text, and a 2-billion-parameter model only makes the judgment calls. Then every field gets checked against the rows it came from.

How it works

Similarity search alone can't answer “season opener” or “most total points.” Every question goes through the same general pipeline. Nothing branches on question ids or wording templates.

  1. 1

    Link & parse

    Match teams, players (accent- and suffix-insensitive), dates, scores, stats and season phase with deterministic rules.

    catalog.py · parsing.py
  2. 2

    Plan

    The LLM proposes filters (won/lost, thresholds, which game, most/least). A filter survives only if the question's own words support it.

    planner.py
  3. 3

    Retrieve

    SQL pulls the candidate games, box scores, recaps and notes. When too many games are left, pgvector ranks the text within them.

    retrieval.py
  4. 4

    Reason

    Python computes order, winners, margins, totals, single-game bests and threshold counts. These become short labeled tables, and each row carries its evidence.

    reasoning.py
  5. 5

    Read

    For text facts, the LLM names the recap or note row that states the answer. A number only recaps contain is read game by game and ranked in Python.

    answer.py
  6. 6

    Verify & cite

    Every field must match its row. Evidence must cover every table the answer cites. If anything fails, it abstains with a reason.

    answer.py

Data

Kaggle “Historical NBA Data and Player Box Scores”, cut to one season. The source has no prose, so recaps are written from play-by-play events (comebacks, go-ahead shots) and availability notes from the box score's did-not-play comments.

Evaluation

Gold answers are computed independently with pandas. Recap questions take their gold from play-by-play facts the pipeline never sees. The test set was written after development ended and run once, with phrasings, players, teams and dates the pipeline never saw.

Reproducibility

Temperature 0 and a fixed seed. Exact vector scans with stable tie-breaks. The same run on the same data gives the same answers.

Run it yourself

Answering a question needs Postgres and a local model, so this hosted page can only show recorded results. Run the project on your machine and this same page gets an Ask box wired to the live pipeline.

  1. 1

    Install the prerequisites

    Docker, Ollama and Python 3.11+. A GPU helps but isn't required.

  2. 2

    Get the code, models and database

    git clone https://github.com/trstewart-max/nba-rag.git
cd nba-rag
ollama pull nomic-embed-text
ollama pull qwen3.5:2b
docker compose up -d db
  3. 3

    Set up Python

    python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
    python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
  4. 4

    Build the data one time, ~15–25 min

    Downloads the season from Kaggle, writes the recaps and notes, loads Postgres and embeds 8.7k documents.

    python -m nba_rag.build
python -m nba_rag.ingest
python -m nba_rag.embed
  5. 5

    Start the server and ask

    uvicorn nba_rag.server:app --port 8000

    Then open localhost:8000. Next time, only docker compose up -d db and this command are needed (with Ollama running).

Questions to try

    It knows the 2025-26 season and eight kinds of question: player stats, team leaders, most N+ games, game results, largest margins, comebacks, plays from recaps and why a player missed a game. Anything else gets a polite “I can't tell from the data.”
